Recommended

GitHub Action: runs in your GitHub

  • We never see your data. It runs on GitHub's own runners, in your account.
  • Free, and uses only a minute of your Actions time a week.
  • Open source: you can read every line it runs.

In a private repository (for example a new one named mastyf-reports), add this file as .github/workflows/mastyf-authority.yml:

name: Mastyf Authority
on:
  schedule: [{ cron: "0 6 * * 1" }]   # Mondays
  workflow_dispatch:
permissions: { contents: read, issues: write }
jobs:
  report:
    runs-on: ubuntu-latest
    steps:
      - uses: mastyf-ai/mastyf-authority/action@main
        with:
          org-token: ${{ secrets.MASTYF_ORG_TOKEN }}

Then Actions → Mastyf Authority → Run workflow for your first report now.

Optional · see the whole organisation

Give the Action a read-only token

On its own, a workflow can only see the repository it runs in. With a read-only token it covers every repository and organisation-level changes: new owners, repositories made public or deleted, protections removed, new deploy keys and admins.

  1. Create a fine-grained token at github.com/settings/personal-access-tokens/new: resource owner = your organisation, All repositories, repository permission Administration: Read-only (Metadata is added for you), organisation permission Members: Read-only. Nothing else.
  2. Save it as a secret in the repository with the workflow: Settings → Secrets and variables → Actions → New repository secret, name MASTYF_ORG_TOKEN.
  3. Run it: Actions → Mastyf Authority → Run workflow, or wait for Monday.

The token is read-only and never leaves GitHub: only your workflow uses it, on GitHub's runner. Some organisations require an owner to approve fine-grained tokens; GitHub will ask if so.

Privacy

What it can see, and why

GitHub asks you to approve each permission when you install. Here is why the app asks for each one.

PermissionLevelWhy
MetadatareadRepository names and whether they are public or private. Every app has it.
ContentsreadGitHub sends push events (force-pushes) only to apps with this permission. The app never reads files, diffs or commit messages.
AdministrationreadTo be told when branch protection or rulesets are removed or changed.
MembersreadTo be told when someone becomes an owner or a collaborator.
DeploymentsreadTo be told when a deploy key is added.
IssueswriteTo post the weekly report, only in a private repository.

Kept, for 90 days

  • The kind of event, and when it happened
  • The account, repository and branch
  • Authority's verdict and its reasons

Never kept or read

  • Your code, diffs, commit messages or file names
  • Anything at all after you uninstall: the app deletes it immediately
  • Reports in public repositories: if you have no private one, nothing is posted

Questions

Good to know

Will it ever block or slow down my team?

No. It runs in shadow mode: GitHub tells the app what already happened, and the app only reports what Authority would have done. Your work is never paused.

Can it read my code?

GitHub requires read access to contents before it will send push events, so the permission is there. The app uses only the event itself (who, which branch, whether it was a force-push) and never fetches files, diffs or commit messages.

Where do the reports go?

To an issue in a private repository the app can see, preferably one named mastyf-reports or .github. If it can see no private repository, it posts nothing and waits until you add one.

What does it cost?

The app is free. If the reports are useful and you want Authority to actually hold risky actions until a second person approves (on GitHub, AWS, Okta, data exports and AI agents), we offer a free 60-day pilot to our first three founding design partners.

What does it not cover?

Only what GitHub sends to apps: it cannot see who viewed or cloned what (that needs GitHub Enterprise's audit log), and personal accounts have no organisation events such as new owners.

How do I remove it?

Uninstall it in your organisation's settings under GitHub Apps. The app deletes everything it kept about your organisation the moment GitHub tells it you uninstalled.
